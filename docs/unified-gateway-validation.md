## 实测发现与修复

- 凭证 gate 最初把任何 pending card 都当阻塞；修为需要明确的前台回合/服务端证据，后台标记优先，保留普通输入安全测试。
- 微信输入状态在 intake 后异步登记过晚导致闪停；改为同步活动登记。
- `/停止` 是转发给 Muse 的原生命令，不能只在本地 CommandHandler 清理输入状态；已在原生命令提交后结束活动。
- 最后实际停止进程时，QQ 事件源把 `CancelledError` 与断线异常一起重连，导致 Ctrl-C 无法退出。已拆分取消路径：关闭 socket、停止心跳并向上抛出取消，新增“不重连”的生命周期回归；重新启动真实 QQ 连接后再按 Ctrl-C，已正常返回 shell 提示符，无重连。
- 启动验证失败且确实无凭证时补回登录通知；暂时网络错误且已有凭证不误报重新登录。仅做离线测试，没有执行真实登录。
- Git Bash/MSYS 会把单独的 `/帮助` 等参数转换为 Windows 路径；真机驱动命令必须关闭路径转换。该现象发生在测试驱动入口，不是桥接命令解析问题；修正驱动调用后实测通过。
- 审查用受控时序复现了共享会话旧 route 退休后的历史串通道；修为独立持久化 causal origins，并记录外通道抑制的消息。测试覆盖另一 worker 首次扫描已经很晚、恢复持久化状态、清空 seen 缓存的情况。
- 次管理员首次自动绑定 main 以前可能跳过 session lock；改为入站先解析并绑定实际 main，再加锁。屏障测试在 POST 返回前注入真实事件 worker，确认释放前零投递、释放后仅次管理员收到。
- 启动登录提示被拒绝以前可能经 gather 关闭所有适配器；改为 best-effort。离线测试覆盖拒绝、未知与异常，网关继续运行。
- 补充所有可变仓库路径碰撞检查；切换账号禁止继承 main seed。旧 OneBot 所有权无法从账号元数据证明时保留原文件、使用新分片，而不是仅信任相同 API 地址。

## 边界与未验证项

- 未进行 QQ 以外平台真机、实际登录/验证码、真实凭证提交或真实邮件发送；由维护者按原约定验证。
- 现场有 Muse `ConnectionLost` / `HandshakeError`，订阅自动重连后恢复；至少一次入站发送结果提示无法确认，未自动重发。不能把现场网络记为全程稳定。
- 第一版没有持久化入站队列；进程退出期间的消息保证依赖平台重投语义。未知/部分出站账本保留，不承诺恰好一次用户可见投递。
- 投递账本与 QQ 被动序号当前保守保留，不自动删除未知记录；高吞吐长期运行需要关注元数据增长。
- 重启后群 `/当前` 保留原绑定；私聊 `UG-RESTART` 遇到结果不确定提示后，实际收到唯一 `UG-RESTART-OK`。没有自动重发入站，也未观察到旧审批卡或旧主动提醒重放。该现场结果不替代受控并发/故障测试。

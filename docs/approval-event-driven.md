# 事件驱动审批与本地发送门禁

## 配置

```json
{
  "muse": {
    "approval": {
      "mode": "manual",
      "notify": true,
      "sync_interval_s": 180
    }
  }
}
```

`sync_interval_s` 是正常运行时 Sentinel 全量补偿同步的间隔，单位为秒，默认 **180**，必须是正整数；布尔值、零、负数、字符串和小数均拒绝。省略该字段使用默认值。不需要修改现有生产配置即可取得新默认值。

原有 `mode`、`notify`、审批决定类型和长期权限范围不变。本文的 180 秒不是自动批准超时，也不是聊天轮询周期。

## 更新来源与线程边界

- 启动验证凭据成功后，先检查 Sentinel `/approvals`，恢复既有待审批，再启动适配器。未成功取得可信状态时，普通消息保持门禁；凭据暂不可用时在恢复后补查。
- 一个独立客户端以空会话参数执行 `daemon/chat.subscribe`，接收账号级 `approvals.snapshot`，不依赖 QQ / OneBot / WeChat 已绑定会话的聊天出站订阅。
- 同一订阅消费前台与后台审批。前台仍按 `thread_id` 管理；具有明确 `background` / `schedule` / `scheduler.cron` 证据的记录进入独立后台队列，不捕获普通聊天输入。
- 同步客户端不是线程安全对象。订阅 worker 独占一个客户端；补偿查询使用独立客户端。状态锁不跨网络调用持有。
- 事件到达即更新内存并唤醒通知循环。全量查询另起异步任务等待同步 RPC，不阻塞新事件的状态提交与人工审批卡通知。
- 正常按 `sync_interval_s` 全量同步。启动、重连、无效快照或缺少终态等恢复情况也会要求补查；失败使用约三秒退避重试。约三秒的本地通知重试唤醒不是正常 GET 周期。

## 普通发送与审批决定

`MuseService.check_approval_gate()` 只读内存，不再在每条普通消息前执行 `GET /approvals`。新绑定的会话可从账号级缓存投影已有待审批，不需要由入站消息触发查询。

- 未初始化、断线后失效或状态不可信：本条消息不发，提示稍后重发。
- 当前会话有前台待审批：本条消息不发，仍展示该会话审批卡。
- 只有后台待审批：不阻塞无关聊天。
- 本地拦下的消息不排队、不在审批后补发。服务端接受 POST 也不代表立刻执行，因此不绕过门禁。
- 用户真正选择审批时，仍刷新远端状态与卡片版本，再提交决定。不确定的决定不自动重发；用户显式重试规则保留。

移除的是**每条普通发送的远程预查**，不是审批决定的一致性检查，也不是本地门禁。

## 状态一致性与恢复

1. 每次连接有独立 generation；结束连接立即作废该代，旧代迟到的事件不能重新打开门禁。凭据在阻塞读取期间轮换时，丢弃该次读出的事件并重连。
2. 校验 `schema_version=1`、整数序号／时间戳与记录结构。重复序号、回退序号和倒退的事件时间不覆盖已有快照；无效快照撤销可信状态并要求补查。
3. 网络查询开始时记录状态版本。请求期间若有较新的事件或连接失效，旧请求成功或失败都不能覆盖较新的状态。
4. 账号级缓存保存尚未绑定聊天的前台待审批，避免后建绑定漏掉门禁。
5. `recent_approvals` 是有界历史。既有 pending 消失却没有明确 `approved` / `denied` / `timed_out` 时，保留门禁并补查该审批详情，不将“没看见”当成“已批准”。
6. 事件不延后全量安全同步的计时；流关闭也不会被当成永久无事件的空闲连接。
7. 退出时通知订阅 worker 停止，由其在有界读取／连接结束后关闭客户端；等待正在执行的同步查询收尾，不将阻塞网络调用直接遗弃在后台。

## 事件快照结构

账号级 `daemon/chat.subscribe` 订阅推送 `event="approvals.snapshot"` 帧：

```json
{
  "type": "event",
  "event": "approvals.snapshot",
  "seq": 2193,
  "ts_ms": 1763383179703,
  "payload": {
    "schema_version": 1,
    "emitted_at_ms": 1763383179703,
    "pending_approvals": [],
    "recent_approvals": []
  }
}
```

- 前台审批通常携带 `scope.thread_id`，按所属会话阻塞普通发送；
- 后台／计划任务审批携带 `display.attention_mode="background"` 或 `scope.requester_source="scheduler.cron"` 等后台标记，进入独立后台队列，不按 `session_scope_id` 强行绑定或阻塞当前聊天。

## 跨来源指纹匹配规则

事件快照、列表查询与审批详情在展示字段和版本号上的细微差异按以下规则归一化，既避免首次选择误判变更，又不放松防误批准校验：

- **旁聊来源注记归一化**：事件快照的 `purpose_summary` 可能在 `short_explanation` 后追加单行旁聊来源注记，而列表查询不含该注记。仅当基础说明与 `short_explanation` 完整匹配且剩余文本严格符合单行旁聊来源注记格式时，在指纹比较中去除该注记；展示仍保留来源说明以减少卡片抖动。不忽略整个 `purpose_summary`，不删任意后缀。
- **初始版本等价规则**：事件或列表可能省略 `message_revision`，详情接口返回初始值 `0`。指纹计算将缺失版本与 `0` 视为等价，但缺失版本不与正版本号等价；后续无版本快照保留此前详情已确认的版本，提交决定仍携带 `expected_message_revision`。
- **严格失效条件**：实际目标／payload、预览文档、基础说明、任意其他目的说明、原生选项顺序或权限范围、有效版本号发生任意变化时，旧选择失效并要求重新选择。

## WebSocket 短超时接收语义

审批订阅使用短超时读取以便及时响应退出与状态同步，底层帧解析遵循以下语义：

- 帧头、扩展长度或正文未收齐即超时时，保留接收进度且不提前消费帧头，下一次读取继续同一帧；
- 分片消息跨超时保留已收片段与 opcode；
- 收到 `ping` 时回复 `pong`，收到 `pong` 不进入 Noise 解密且不消耗接收 nonce；
- 订阅流关闭时交付最后一批完整事件后报告断线，普通传输错误不作为空闲超时吞掉。

## 安全与行为边界

- 前台审批挂起期间，直接向服务端 `POST /chat/stream` 仍可能返回 `200` 与 `message_id`，但该确认不代表消息已执行或已进入可见历史，因此桥接层保留本地门禁而不依赖服务端拒收。
- Worker 模式下完整 WebSocket query 参数会经过用户自建的 Cloudflare Worker，需自行管理对应请求日志策略。
